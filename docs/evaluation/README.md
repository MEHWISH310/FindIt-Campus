# Evaluation

Generated by `backend/generate_evaluation.py` (real `fusion.composite_score()` and `MatchCalibrator` code). Every report states at the top whether it was built from real or synthetic pairs.

| File | What it shows |
|---|---|
| `precision_recall.md` / `.png` | Fused score vs text-only and image-only baselines (AUC-PR) |
| `calibration_report.md` / `calibration_curve.png` | Reliability diagram and Expected Calibration Error |
| `disambiguation_impact.md` / `.png` | Effect of disambiguation on picking the right item among close candidates |
| `missing_modality_impact.md` / `.png` | Match quality with text only vs text + image |

## Data

The current reports use **8 real, human-confirmed labelled pairs** (7 matches, 1 rejection) exported from the production DB. That sample is too small for conclusions; treat the numbers as preliminary until more handovers and rejections accumulate.

## Regenerate

```bash
cd backend
python export_labelled_pairs.py                          # writes labelled_pairs.csv from the DB
python generate_evaluation.py --csv labelled_pairs.csv   # real pairs
python generate_evaluation.py                            # synthetic fallback (illustrative only)
```
